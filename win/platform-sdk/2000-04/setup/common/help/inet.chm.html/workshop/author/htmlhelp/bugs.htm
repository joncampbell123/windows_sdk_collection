Known Bugs in HTML Help 1.1

Microsoft Corporation

Updated: February 26, 1998

HTML Help Workshop allows you to edit HTML files. When you quit the program, it gives you the opportunity to save the files under a new name. If you click Cancel, and then try to continue working with the project, HTML Help Workshop will crash. Workaround: Do not click the Cancel button on this dialog box. Instead save the file under another name. Delete the file later if necessary.

If you add a custom bitmap for a table of contents icon, HTML Help Workshop sets a width value for the icon in its <OBJECT> tag. If you subsequently attempt to edit the width value, any changes you make will not be saved. Workaround: none.

Defining some information types in categories and others not in categories in the same project does not work. In the OCX, the information types without categories may not show up as choices in the selection UI.

Defining identical information types in more than one category does not work properly. In the OCX, the information types will only display as choices for the first category.

In HTML Help Workshop, if you define one or more information types, and then remove all information types, you are left with a blank information type that cannot be deleted in the list. Workaround: none.

If you define Exclusive information types without categories, they will not act properly in the OCX. They will appear as radio buttons in the information types Customize dialog box, but users will not be able to select them. Workaround: none.

Additional bugs and items of note can be found in the Readme contained in help for HTML Help Workshop.
