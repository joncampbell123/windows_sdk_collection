Summary

Specifying typography on the Web has been -- and continues to be -- a major headache for most designers and publishers. This article highlights a few of the technologies and methods you can utilize to make more efficient and eye-catching use of type on your Web pages.

Introduction

It's a widely accepted canon in design circles that good typography improves communication and can influence the reader. If, like me, your choice of wine has more to do with price and label design than the vintage and vineyard, you'll know what I'm talking about. Designers and publishers constantly make use of typography to set the tone of their work and establish a brand identity; often it's the really small details, the nuances, that make the difference between effective and mediocre typographic work. Spacing, size, weight, balance, and contrast all work together in subtle ways to shape the page.

Until recently, designers working in the medium of the Web have been denied the level of control necessary to create effective typography. Despite all the publicity about new technologies capable of making our Web pages do anything shy of performing bodily functions, designers have had about as much control over text formatting as the Sumerians had 5,000 years ago when they were pressing reed styluses into clay tablets. Because HTML was never designed to provide control over a document's appearance, the markup language has been restricted to a choice of seven font sizes with bold and italic styles.

This lack of a viable, usable mechanism for specifying typography has been only one of the problems Web designers have had to face. The difficulty of designing a page so that it will display well on variable (and varying) output devices has been significant. For all the shortcomings of the clay slab as a publishing platform, at least the cuneiform writer knew exactly what the party he gave it to was going to see. The threat of a hernia loomed whenever anyone tried to move the slab, and it wouldn't have made for good, clean reading in the bathtub -- but by and large, the wedge-shaped marks made before the tablet was baked were the same marks read long afterwards. On the Web , no one can guarantee that the page they've designed will look exactly the same on all machines; often a page will look substantially different when viewed on different system setups.

Additional complications have been the difficulty of knowing which fonts are installed on users' systems, and a dearth of high-quality fonts designed for the screen and readily available. Perhaps the biggest problem of all is that the Latin script, English language-centric fonts in common use are far from sufficient if the Web is to become a truly global and multilingual publishing environment.

With all these difficulties, it's not hard to see why the issue of typography on the Web has started to receive more and more attention.

Why Bother with Text?

With all the difficulties of controlling page layout and type accurately, it's hardly surprising that designers have resorted to tables and graphics to build pages. Designers wanting to achieve a particular visual effect, or to use certain fonts, or to layer or accurately position page elements have had little choice but to use bitmap graphics.

But using "live" fonts and text in Web pages has real advantages over the use of .GIFs and .JPEGs. Page downloading and rendering time is significantly decreased, and file sizes are reduced. If the text specified in HTML uses scaleable outline fonts, it's easy to change the size of the text while retaining the quality. This means the page can be printed out without the text becoming jagged.

Text can be searched, indexed, and cut and pasted -- and it is a lot easier to edit than a graphic. Localizing text is much easier than having to recreate a graphic file. And as the technologies outlined below show, it's amazing what kind of visual effects can be achieved through the use of nothing more than text, fonts, and some clever HTML.

Specifying Typography: Cascading Style Sheets

Cascading Style Sheets (CSS) allow the addition of style sheet information to a Web page, dramatically increasing the typographic options available to the designer, and making Web site formatting much easier. Because style sheets, if used properly, help to separate a document's content from its presentation, they have been happily accepted by the SGML and HTML purists, to whom document structure is everything.

The CSS specification is an extension to HTML, and is a standard recommended by the World Wide Web Consortium (W3C). Browser support for CSS is quickly gaining momentum, with the specification now supported in Internet Explorer 3. x, Internet Explorer 4.0, and Netscape Navigator 4.0 and Communicator. For a comprehensive overview, see George Young's article Cascading Style Sheets in Internet Explorer 4.0.

Specifically, there are three chief advantages to using CSS over plain HTML:

  • Extensive control of typographic properties
  • Accurate positioning of elements
  • Easy maintenance of pages

Extensive control of typographic properties

Many of the approximately 50 properties contained in the CSS specification relate to the use of type, affording the designer control of numerous typographic variables. Through the use of style sheets, it's possible to change type face, size, color, weight, interlinear spacing, intercharacter spacing, indents, and margins. The units of measurement specified can be points, picas, pixels, percentages, millimeters, inches, and ems -- quite a bit more sophisticated than <FONT SIZE 1 to 7>. For more information on CSS properties, see the article Style Sheets: A Brief Overview for Designers and visit the CSS section in the MSDN Online Web Workshop's DHTML, HTML and CSS area. To see the kind of Web page design possible using CSS, visit Microsoft Typography's CSS Gallery.

Accurate positioning of elements

Traditionally, it has been really hard to position elements -- including text elements -- accurately on the page using HTML. The CSS specification as implemented in Internet Explorer 4.0 and Netscape Navigator addresses this issue.

Through the use of the absolute positioning property, it is now possible to specify where an element should be positioned on the page in both the x and y coordinates and zorder, which specifies whether the element should be positioned on top of or underneath other elements. You can find out more about CSS positioning in the DHTML, HTML & CSS area of the SBN Workshop. Nadja Vol Ochs discusses design and element positioning in her column Is Your Site Made with Style? For the W3C specification, visit the positioning area of the W3C Web site.

Easy maintenance of pages

Another attraction of CSS is that the style sheets can be used either by just one of the pages of a site, or by a collection of pages that refer to the same style sheet. This significantly reduces the amount of size and time required to format all the pages on a site -- and it helps to ensure consistency across a range of material, eliminating such problems as "why is my heading four points smaller on this page?" If you decide to change the typeface for an element, just change the font specified in the appropriate style sheet; the change will be propagated throughout all the HTML files referring to that same style sheet. Robert Hess discusses this further in his article Linked Style Sheets.

Dynamic HTML and CSS filters

CSS can be expanded further when used in conjunction with Microsoft Dynamic HTML -- an open, standards-based technology that allows properties to change dynamically in response to a particular event. The event May be a mouseover, a click, a window size change, a timed event, or a response to another action on the page. Every element of the HTML page is now exposed as part of the Internet Explorer 4.0 object model, meaning that through scripting, it's possible to alter any style used in the document. A DHTML page can be as simple as a collapsible contents page, where the text remains hidden until a heading is clicked, or as complex as a page in which timed events and changing coordinate positions can be used to move text around the screen, scale it, and change its color. Because all the code necessary to achieve these effects is just HTML text, the download time for DHTML pages can be very short -- much less than that required for an animated graphic or an applet. For more information, visit the DHTML, HTML & CSS area in the MSDN Online Web Workshop.

CSS filters provide a way of transforming text and graphics. It's now possible to apply a blur, or a glow, or a drop shadow (to name just a few of the possible effects) to the contents of a page just by adding the filter attribute to the style sheet and setting the appropriate properties and values. Filters can even be chained together to produce very complicated visual effects. One of the benefits of applying CSS filters to text is that it's no longer necessary to create graphics in download text. Nadja Vol Ochs introduces the topic of CSS filters in her MSDN Online Voices Design Discussion column. For more comprehensive information, see the CSS Attributes section of the SBN Workshop's DHTML, HTML & CSS area.

Using Fonts in Web Pages

Although Cascading Style Sheets provide designers with a great deal of control over font specification, but they only work in conjunction with the fonts installed on the user's system. It doesn't matter how extensive style sheet information is if a user doesn't have the specified fonts installed on his system -- in which case the page will be rendered using default fonts. Since character widths and sizes can vary widely between fonts, line endings can change when fonts are substituted, and the page May break.

In the past, the only way to avoid this problem has been to use fonts the user is more or less certain to have installed. This has been a serious impairment to the creativity of designers, for lovely though they May be, Times New Roman and Arial -- and various flavors thereof -- are slightly too bland and overused for most designers' tastes.

Web fonts

To extend the repertoire of widely installed fonts, Microsoft has made available a set of high-quality fonts that can be freely downloaded and distributed (with certain limitations). These fonts have been specifically designed to look great on the screen. In many cases, they contain all the characters necessary to set Greek and Cyrillic text in addition to all the European languages. And because the fonts are regular TrueType fonts, they're not limited to Web use; they can be used in other applications and maintain a high-quality appearance when printed. Many of the fonts are installed automatically with Internet Explorer 3.x and Internet Explorer 4.0, and all are available for both Mac and PC platforms from the Microsoft Typography Web site.

Designers always want new fonts to work with -- and limiting them to 10 fonts is in some respects just as bad as limiting them to two. It's only a matter of time before a new project comes up, and they want new fonts for it.

Font embedding

To compensate for this problem, Microsoft Internet Explorer 4.0 introduces font embedding to the World Wide Web. Font embedding has been a feature of Microsoft applications such as Word and PowerPoint® for several years. It allows the fonts used in the creation of a document to travel with that document -- ensuring that a user sees the pages exactly as the designer intended them to be seen.

Because most Web pages never use all the characters contained in a font, it doesn't make sense to send the entire font to the client machine. In many cases, only about 70 characters are required to compose a page -- the upper- and lowercase characters and a few punctuation symbols. Font embedding sends to the user character subsets containing only the characters needed to display the page.

To help you embed fonts in your Web pages, Microsoft has developed a Web Embedding Fonts Tool (WEFT). The Microsoft Typography site provides an overview of WEFT, as well as information about checking and specifying fonts, running the WEFT Wizard , dynamic content , and a WEFT FAQ . You can also download for free a public preview version of the tool.

Coming Soon: The OpenType Font Format and OpenType Layout

OpenType is an extension to the TrueType font format and has been jointly developed by Microsoft and Adobe. It allows fonts to contain either TrueType or PostScript data, or both. OpenType promises to make font development, management, and use much easier. Designers and users will no longer need to be concerned about font formats, or which kind of data the fonts contain, because font installation and use will be completely transparent to them. The Operating System and application will automatically resolve which kind of data is contained in the font file and use it accordingly.

OpenType Layout (formerly known as TrueType Open), a further extension to the OpenType font format, will extend the capabilities of fonts to support sophisticated and high-quality international typography. OpenType Layout will enable many advanced typographic features, such as automatic ligature substitution, optical positioning, baseline adjustments, and the use of proper fractions, superiors, inferiors, small capitals, and alternate numerals. Support for this functionality will be included in the operating system and utilized by applications.

Conclusion

These new technologies are not just making it as easy to specify typography on the Web as in print, but are set to change the way we use typography altogether. There are significant advantages to using text, as opposed to graphics, on the Web, and technologies such as Cascading Style Sheets, Web fonts, font embedding, and Dynamic HTML are finally giving designers the control they need to tame their typography.

Simon Earnshaw is a typographic engineer with Microsoft's Typography group.
